## Prompt concepts explained with code

### What this application teaches

A property test checks an invariant across generated inputs. Here decoding an encoded byte array must reproduce every original byte, not merely match a few hand-picked examples.

### Follow the implementation

From [demo.mjs, lines 1-11](demo.mjs#L1) (source excerpt; run the full application using the command above):

```javascript
import fc from "fast-check";
import assert from "node:assert/strict";
import { encode, decode } from "./binary.mjs";
fc.assert(
  fc.property(fc.uint8Array({ maxLength: 1024 }), (bytes) => {
    assert.deepEqual(decode(encode(bytes)), bytes);
  }),
  { numRuns: 1000, seed: 42 },
);
assert.throws(() => decode(Uint8Array.of(0, 0, 0)));
console.log("1000 seeded round trips plus truncated-header boundary passed");
```

### Why this produces the observed result

A fixed seed makes a failing generation reproducible, and the explicit truncated-header case covers a rejection contract alongside the round-trip property.

Compare the behavior described above with [the captured run](observed-output.txt). That file records one validation run; timing, generated paths, ports, and identifiers can differ on your machine. Read the assertions in [demo.mjs](demo.mjs) to see which outcomes the demo actually checks.

### Student exercise

Temporarily corrupt the codec's length calculation and inspect the generated failing case. Explain why reproducible seeds help debugging while varying seeds broadens exploration.
