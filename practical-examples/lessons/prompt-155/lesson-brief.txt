Architecture flow: GitHub Actions (npm ci, checks, image build) → image running as a non-root USER node → Compose: 2 api replicas behind NGINX, a worker, PostgreSQL, Redis → telemetry: pino JSON logs with trace ids, /metrics, OTLP traces. One focused snippet, coordinated shutdown, src/shutdown.mjs (app, worker, pool and sdk supplied), exactly:
const DEADLINE_MS = 10_000;
let stopping = false;

export async function shutdown(signal) {
  if (stopping) return;
  stopping = true;
  app.log.info({ signal }, 'shutting down');
  const timer = setTimeout(() => process.exit(1), DEADLINE_MS);
  timer.unref();
  await app.close();
  await worker.close();
  await pool.end();
  await sdk.shutdown();
  clearTimeout(timer);
}

process.once('SIGTERM', shutdown);
process.once('SIGINT', shutdown);
Teach: readiness returns 503 as soon as stopping is true (see Prompt 139); app.close() stops new connections and waits for in-flight requests; worker.close() lets active jobs finish; sdk.shutdown() flushes telemetry; the deadline is shorter than the Compose stop_grace_period. Metrics labels use route templates, never raw URLs or user ids. Connection budget: 2 replicas × pool max 10, plus the worker, must stay under the database limit (example allocation, not measured). Commands, each on one line: npm ci, docker compose up -d --build, docker compose stop db (dependency-outage rehearsal), docker compose up -d --force-recreate api (replica replacement).
