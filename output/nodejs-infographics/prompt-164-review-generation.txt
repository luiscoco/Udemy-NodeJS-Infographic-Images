Badge: Prompt 164. Title: Recovering Asynchronous Context
Implementation Prompt (quote this exercise, condensed only if needed): Demonstrate context loss at a deferred callback boundary. Capture context with AsyncLocalStorage.bind() and snapshot(), verify concurrent request IDs stay separate, and design a legacy callback adapter using AsyncResource when required.
Curated content (highest priority):
Course baseline: Node.js 26.13.1. bind() and snapshot() are stable on the course baseline. run() scopes the store; calling plain later outside the original context sees undefined. bind captures execution context for a specific function; snapshot returns a runner that invokes supplied functions in captured context. Captured context is a reference to the store, not a deep clone of its values. This example models a callback boundary; ordinary supported promises/timers already preserve context. For custom callback adapters or worker-pool integrations, create AsyncResource in the intended context, use runInAsyncScope and call emitDestroy when owned work is complete. Do not claim arbitrary callbacks or worker-thread messages automatically preserve context. Files (copy exactly):
context-bridge.mjs:
import { AsyncLocalStorage } from 'node:async_hooks';

const context = new AsyncLocalStorage();
let plain, bound, captured;

context.run({ id: 'A' }, () => {
  plain = () => context.getStore()?.id;
  bound = AsyncLocalStorage.bind(plain);
  captured = AsyncLocalStorage.snapshot();
});

console.log(plain());
console.log(bound());
console.log(captured(plain));
